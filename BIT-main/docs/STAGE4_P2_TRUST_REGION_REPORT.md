# 阶段4 P2：LOO 预筛选与单调验证信赖域报告

日期：2026-08-23

## 1. 机制

本轮将短步 LOO 从直接软权重改为候选更新前的风险预筛选，并把真实验证损失
作为模型发布的硬信赖域：

```text
u_i = L_val(25-step leave-one-out_i) - L_val(25-step full)

parent reject 或 u_i <= 0  -> 删除观测
u_i > 0                    -> 保留观测

保留观测少于2帧           -> 回滚稳定模型
否则执行200步候选优化
L_val(candidate) <= L_val(stable) -> 提交候选
否则                            -> 回滚稳定模型
```

验证损失在同一事件、同一验证帧集合和同一渲染配置下分别测量稳定模型与候选模型，
不使用训练损失代替。每个事件记录 proposed、stable、最终发布指标、提交状态、
回滚原因和 LOO 计算耗时。

实现位置：

- `scripts/stage4_influence.py`：`short_loo_filter_weights` 与
  `monotone_validation_commit`；
- `scripts/replay_stage4_p2_geometry.py`：精确候选优化、真实验证和 rollback；
- `scripts/evaluate_stage4_p2_influence.py`：将 committed/rolled_back 最终模型
  纳入配对验收；
- `config/stage4_p2_loo_trust_region_v1.json`：可复现实验配置与哈希。

## 2. 开发实验

数据固定为 `duplo_dude/01`、`toy_plane/02` 的 seed 59–64，共15个候选事件。
公式固定为25步 LOO、utility 阈值0、至少2个训练观测、200步候选优化和0容忍的
真实验证 IoU 单调条件。

| 指标 | 结果 |
|---|---:|
| 候选提交 | 8/15 |
| 回滚稳定模型 | 7/15 |
| 因预筛不足2帧回滚 | 6 |
| 因真实 IoU 未下降回滚 | 1 |
| 单调性违规 | 0 |
| 已提交候选最小真实 IoU 改善 | 0.001430 |
| 最终模型相对稳定模型平均 ΔIoU loss | -0.002163 |
| 最终模型相对原始候选平均 ΔIoU loss | +0.001217 |
| 相对原始候选改善事件 | 5/15 |
| bootstrap 95% CI | [-0.000436, +0.003276] |
| 位姿不一致性平均变化 | -0.000408 |
| 时序标准差平均变化 | +0.001886 |
| LOO 平均耗时 | 24.32 s/事件 |

按 seed 相对原始候选的平均 IoU loss 变化：

- seed 59：-0.003029；
- seed 60：+0.003882；
- seed 61：+0.001107；
- seed 62：+0.001673；
- seed 63：+0.000936；
- seed 64：+0.001232。

## 3. 判定

信赖域机制本身成立：所有最终模型都满足真实验证 IoU 不高于稳定模型，8个候选
严格改善稳定模型，7个事件安全回滚，单调性违规为0。这解决了“有害候选仍被
发布”的安全问题。

但 LOO 硬预筛后的候选只在2个可生成事件中优于原始候选；最终策略相对原始候选
仅改善5/15，时序稳定性退化，五个 seed 的平均方向为负向。因此开发验收
`pass=false`，当前版本标记为 `development_rejected_not_frozen`：

- 不接入在线发布路径；
- 不消耗新的独立 seed；
- 保留为安全更新机制和论文消融；
- seed 65–67 已在上一实验使用，不得重新声称为独立集。

## 4. 下一步

下一版应采用“双候选信赖域”：正常全量候选与 LOO 预筛候选都在同一验证集合
评估，最终从稳定模型、全量候选、LOO候选中选择真实验证 IoU 最低者。这样可以
保持单调安全，同时避免 LOO 排序错误丢失原始候选的有效更新。必须同时报告计算
开销，并在开发通过后再预注册全新的独立 seed。
