# 阶段4 P2：多指标双候选信赖域报告

日期：2026-08-23

## 1. 预注册方法

本轮在查看重选结果前固定：

1. 保留 stable、full、LOO 三个候选；
2. full 永远可行；
3. stable 与 LOO 只有在相对 full 的位姿不一致性和时序标准差均不增加时可行；
4. 在可行集合中选择真实验证 IoU loss 最低者；
5. 比较容差固定为 `1e-12`，不搜索阈值。

开发集为 seed 59–64。只有全部满足下列标准才冻结，并运行 seed 68–70：

- IoU、位姿、时序逐事件零退化；
- bootstrap IoU 95% CI 上界不大于0；
- 至少50%事件严格改善；
- 至少4/6个seed严格改善，其余seed不退化。

协议位于 `config/stage4_p2_multimetric_trust_region_protocol.json`。

## 2. 开发结果

复用上一轮同次计算并完整保存的 stable/full/LOO 指标进行确定性重选，没有重新
训练、搜索阈值或查看 seed 68–70。

| 指标 | 结果 | 验收 |
|---|---:|---|
| stable / full / LOO 入选 | 2 / 11 / 2 | 诊断 |
| IoU逐事件退化 | 0/15 | 通过 |
| 位姿逐事件退化 | 0/15 | 通过 |
| 时序逐事件退化 | 0/15 | 通过 |
| 平均 ΔIoU loss vs full | -0.000450 | 通过 |
| bootstrap 95% CI | [-0.001007, -0.0000381] | 通过 |

| 严格改善事件 | 4/15（26.7%） | 未通过，要求≥50% |
| 严格改善 seed | 3/6 | 未通过，要求≥4/6 |

严格改善出现在 seed 59、60、64；seed 61、62、63 均为持平，无 seed 退化。

## 3. 可行域诊断

- stable 在15个事件中只有2个可行：1个因位姿退化被排除，13个因时序退化被排除；
- LOO 在9个可生成事件中只有3个可行：5个存在位姿退化，4个存在时序退化；
- 最终11/15事件选择 full。

这说明选择器正确实现了多指标零退化保证，但候选生成目标仍主要优化掩码 IoU，
没有主动产生位姿和时序同时可行的几何。问题不应通过在相同开发集上放宽阈值
解决，而应改进候选优化目标。

## 4. 阶段判定

最终 `pass=false`。按照预注册顺序：

- 不冻结当前公式；
- 不运行 seed 68–70，三个 seed 保持完全未使用；
- 不接入在线发布；
- 当前版本作为“多指标安全可行域”消融和离线教师骨架保留。

机器可读结果：

- `config/stage4_p2_multimetric_trust_region_v1.json`；
- `baseline/moped/stage4_p2_offline_replay/capture/analysis/development_s59_64/multimetric_trust_v1_evaluation.json`。

## 5. 下一研究优先级

保持零退化选择器不变，修改 LOO 候选的200步优化目标：加入可微的位姿扰动一致性
和跨验证帧稳定性正则，使候选在生成阶段进入多指标可行域，而不是生成后大量被
过滤。公式应先在 seed 59–64 内做嵌套消融；开发通过后重新冻结，seed 68–70
仍可作为独立验证集。
