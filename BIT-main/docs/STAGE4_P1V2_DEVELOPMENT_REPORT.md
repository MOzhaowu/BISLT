# 阶段4 P1-v2开发与公式冻结报告

日期：2026-08-23

## 结论

P1-v2开发集已完成：原确认v1的95帧与问题序列seed 47–52新增36帧合并后，
共131个对齐关键帧（危险87、安全44），覆盖10个对象/序列。逻辑回归融合仍受
跨对象概率漂移影响；最终冻结不拟合对象权重的`q_pose`因果风险增幅，只允许将
父门控的`accept`降为`downweight`，不允许升级决策或新增硬拒绝。

冻结候选在严格序列LOSO上的结果为：危险保护率83.9%，相对父门控60.9%提高
23.0个百分点；安全误拒率4.5%，安全非接受率45.5%。`duplo_dude/01`危险保护
由37.5%提高到100%，`toy_plane/02`由87.5%提高到100%。序列级20,000次配对
bootstrap的危险保护增益95%区间为`[+6.9, +43.8]`个百分点。

以上结果仅用于方法选择，不能作为独立性能证据。P2仍保持阻塞，直到未查看的
seed 53–58再确认通过全部预注册门槛。

## 失败候选与技术判断

- 稠密逐帧Hessian历史百分位与稳健z分数在问题序列内部有信号，但全局逻辑回归
  发生方向反转，AUROC仅0.145/0.141，未改善`duplo_dude/01`；
- `q_mask*q_pose`、局部轮廓残差、Hessian绝对量和学习式因果融合均无法同时修复
  两个问题序列；
- 直接使用有物理方向约束的`q_pose`风险增幅可避免训练集失败率与对象偏置导致的
  阈值抵消，是当前唯一同时满足总体安全门槛并严格改善两个问题序列的候选。

## 冻结方法

对每次运行的关键帧按时间排序：

```text
r_t = log((1-q_pose_t)/q_pose_t)
s_t = max(0, r_t - min_{j<=t} r_j)
```

当父决策为`accept`且`s_t >= 0.08361776899461498`时，将其降为`downweight`；
其余父决策保持不变。首帧得分为0，当前帧加入历史最低点不会引入未来信息。

冻结配置见`config/stage4_p1v2_reconfirmation.json`，其中记录了实现、开发数据、
汇总结果的SHA256，以及seed 53–58再确认的样本、bootstrap和停止规则。

## 再确认门槛

1. 总体安全误拒率不超过10%；
2. 总体安全非接受率不超过50%；
3. 危险保护率不低于冻结父门控；
4. 两个问题序列均不退化且至少一个严格改善；
5. 至少3个seed同时包含安全和危险关键帧，混合标签seed方向一致；
6. seed聚类bootstrap不显示显著反向变化。

全部通过后才能进入P2离线回放；否则继续P1-v2安全性修复，不根据再确认标签重调
本轮阈值。
